## SQL Injection Pattern Overview
SQL injection occurs when unsanitized user input is concatenated or interpolated into SQL queries.

### Key Components
1. **SQL Sinks**: Functions that execute SQL (execute, query, exec, executeQuery, etc.)
2. **Tainted Sources**: User input (params, request data, user input)
3. **Sanitizers**: Parameterized queries, prepared statements, query builders with placeholders

### Language-Specific Patterns

**Ruby/Rails:**
- Dangerous: `Model.where("name = '#{params[:name]}'")`, `ActiveRecord::Base.connection.execute(query)`
- Safe: `Model.where("name = ?", params[:name])`, `Model.where(name: params[:name])`

**Java/JDBC:**
- Dangerous: `statement.executeQuery("SELECT * FROM users WHERE id = " + userId)`
- Safe: `preparedStatement.setString(1, userId)`

**JavaScript/Node:**
- Dangerous: `db.query("SELECT * FROM users WHERE id = " + req.params.id)`
- Safe: `db.query("SELECT * FROM users WHERE id = ?", [req.params.id])`

**Python:**
- Dangerous: `cursor.execute("SELECT * FROM users WHERE id = " + user_id)`
- Safe: `cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))`

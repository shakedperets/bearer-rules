## SQL Injection Pattern Overview
SQL injection occurs when unsanitized user input is concatenated or interpolated into SQL queries.

### Key Components
1. **SQL Sinks**: Functions that execute SQL (execute, query, exec, executeQuery, etc.)
2. **Tainted Sources**: User input (params, request data, user input)
3. **Sanitizers**: Parameterized queries, prepared statements, query builders with placeholders

### Language-Specific Patterns

**Ruby/Rails:**
- Dangerous: Model.where with string interpolation or concatenation
- Safe: Model.where with placeholders or hash syntax

**Java/JDBC:**
- Dangerous: statement.executeQuery with string concatenation
- Safe: preparedStatement.setString with parameter binding

**JavaScript/Node:**
- Dangerous: db.query with string concatenation or template literals
- Safe: db.query with parameter placeholders

**Python:**
- Dangerous: cursor.execute with string formatting or concatenation
- Safe: cursor.execute with parameter placeholders

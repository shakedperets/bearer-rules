## Bearer Rule Syntax - Critical Rules

### Variable Capture Syntax
- ALWAYS use `$<VAR>` for variable captures, NOT regex groups like `(.+)` or `(.*)`
- Example: `$<SINK>($<TAINTED>)` ✓
- Example: `execute\((.+)\)` ✗ (WRONG - this is regex, not Bearer syntax)

### Pattern Structure
- Keep patterns simple and focused
- Use `filters` to narrow down matches, don't make patterns overly complex
- Each pattern should match a broad set of code, then use filters to refine

### Auxiliary Blocks
- Auxiliary blocks are ESSENTIAL for defining reusable detectors
- Define detectors for sinks (dangerous functions), sources (user input), and sanitizers
- Use clear, descriptive names for auxiliary detections

### Filter Variables
- `variable:` specifies which captured variable to filter
- `detection:` references an auxiliary block
- Use `not:` for sanitizer definitions (things that make code safe)

### Common Mistakes by LLMs
1. Using regex syntax instead of Bearer's $<VAR> syntax
2. Forgetting auxiliary blocks entirely
3. Making patterns too specific instead of using filters
4. Not using `not:` for sanitizers
5. Incorrect YAML indentation (use 2 spaces)
6. Missing the `message` field

### YAML Structure Template
```yaml
languages: [language]
severity: high|medium|low
metadata:
  description: "Clear description of what this detects"
  cwe_id: "XXX"  # CWE number as string
patterns:
  - pattern: |
      $<CAPTURE>
    filters:
      - variable: CAPTURE
        detection: detector_name
auxiliary:
  detector_name:
    patterns:
      - pattern: "specific_pattern"
  sanitizer_name:
    patterns:
      - not:
          detection: safe_check
message: "Human-readable message for developers"
```

### Language-Specific Notes
- **Ruby**: Use method names without parentheses when applicable
- **Java**: Include package/class context when needed
- **JavaScript**: Consider both function calls and method calls
- **Python**: Remember Python uses significant whitespace

Always produce valid YAML that Bearer can parse and execute.
